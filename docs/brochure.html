How it works

  1. Set up a workstream for each function

    Each part of the organisation gets a workflow of its own.

  2. Put its tasks on a Kanban board

    Every task sits in a column showing its stage.

  3. Work the board together

    Colleagues and outside partners with guest logins work on the same board.

  4. Keep leaders informed

    Link to Project Portfolios for structured updates. Export to Excel any time.

Why a board suits operational work

  • See the whole flow. Nobody has to ask where a request has got to.
  • Spot where work waits. Cards piling up in one column show the bottleneck.
  • Finish before starting more. Teams pull new work in when they have room.

Runs alongside Agile Sprints

Teams with a mixed delivery model keep Scrum work in Agile Sprints and operational, ad-hoc work in Group WorkStreams.

Agile Sprints · Scrum delivery

Disciplined sprints, without the admin.

One structured place for epics, stories, sprints and releases, with real-time progress and stand-up reporting built in. It stays lightweight, so the process never gets in the way of the work.

Plan

Epics and user stories in a prioritised backlog. Estimate in story points and plan each sprint against team capacity, with the sprint goal clear before work starts.

Run

A configurable sprint board shows work in progress, finished work and anything blocked. Stand-up reporting is produced automatically, and progress is tracked in real time.

Review

Sprint completion, velocity and carried-over work for every sprint, plus the trend across sprints. Support for sprint reviews.

Release

Releases that span one or more sprints, with each story assigned to the version it will ship in. Epics laid out on a timeline.
